# 07 · 数据模型与存储

> 持久化走 admin-service 的 MySQL（ADR-11）：situation-service **不直连 DB**，通过调 admin-service 新增的 CRUD 接口读写。DB 表与 Controller 由 admin-service（Java/Spring Boot）统一管理。

## 1. 存储分层

```
situation-service  ──HTTP──►  admin-service(/api/admin/situation/*)  ──JDBC──►  MySQL
   (编排/聚合)                    (CRUD/权限/分享)                          (持久化)
```

- situation-service 负责「生成产物内容」，调 admin-service 落库。
- admin-service 负责「数据管控」：表结构、CRUD、按 `X-User-Id`/`X-Team-Ids` 过滤、分享 token。
- 草稿态（draft）不落 MySQL，存 situation-service 内存/缓存（TTL）。

## 2. MySQL 表设计（admin-service 管理）

### 2.1 situation_report（态势产物主表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | varchar(40) PK | reportId，如 `r_20260810_xxxx` |
| title | varchar(200) | 标题（LLM 生成或用户编辑） |
| query | text | 原始提问 |
| source | varchar(20) | `manual`/`qa`/`indicator`/`evaluation` |
| user_id | varchar(64) | 创建人 |
| team_ids | varchar(255) | 团队 id 逗号分隔 |
| status | varchar(20) | `generating`/`ready`/`partial`/`failed` |
| snapshot_json | longtext | **完整产物快照**（charts/map/narrative/datasets 的 JSON） |
| share_token | varchar(64) | 分享 token，null 表示未分享 |
| created_at | datetime |  |
| updated_at | datetime |  |

> v1 采用 `snapshot_json` 存完整快照，避免过度拆表；后续需要按图表检索/统计再拆子表（Q-02）。snapshot 结构与 [04-接口契约.md](./04-接口契约.md) §4 Report 一致。

### 2.2 situation_share（分享表，可选独立；亦可复用主表 share_token）

v1 直接用主表 `share_token` 字段；若需过期/审计再建独立表：

| 字段 | 类型 | 说明 |
|------|------|------|
| token | varchar(64) PK |  |
| report_id | varchar(40) | FK → situation_report.id |
| expires_at | datetime | null = 永不过期（Q-04） |
| created_at | datetime |  |

## 3. admin-service CRUD 接口（新增）

挂在 `/api/admin/situation/*` 下（admin-service 不 rewrite `/api`，注意前端代理 `/api/admin` 不重写路径）。

| 方法 | 路径 | 作用 | 调用方 |
|------|------|------|--------|
| POST | `/api/admin/situation/reports` | 创建产物（落 snapshot） | situation-service |
| PUT | `/api/admin/situation/reports/:id` | 更新（生成完成/编辑） | situation-service |
| GET | `/api/admin/situation/reports` | 列表（分页 + userId/teamIds 过滤） | situation-service 透传 / 前端直连 |
| GET | `/api/admin/situation/reports/:id` | 详情 | situation-service 透传 / 前端直连 |
| DELETE | `/api/admin/situation/reports/:id` | 删除 | situation-service 透传 |
| POST | `/api/admin/situation/reports/:id/share` | 生成 token | situation-service |
| GET | `/api/admin/situation/share/:token` | 公开查看（不需登录） | 前端直连 |

> 前端实际调用路径：列表/详情走 `/api/situation/reports`（situation-service 透传），分享查看走 `/api/situation/share/:token`。situation-service 内部再调 admin-service 的 `/api/admin/situation/*`。这样前端只对接 situation-service 一个入口，admin-service 接口对前端不可见。

### 3.1 响应格式
统一 `{success, message, data}`（admin-service 现有约定）。

### 3.2 权限
- 列表/详情/删除按 `X-User-Id`/`X-Team-Ids` 过滤（admin-service 现有 skill governance 头约定）。
- 分享查看 `/share/:token` 不校验登录态。

## 4. situation-service 调用 admin-service 的实现

```python
# store/admin_client.py（示意）
import os, urllib.request, json, logging
logger = logging.getLogger("situation-service")

ADMIN_SERVICE_URL = os.getenv("ADMIN_SERVICE_URL", "http://localhost:10258")

def save_report(report: dict) -> dict:
    """生成完成后调 admin-service 落库。"""
    url = f"{ADMIN_SERVICE_URL}/api/admin/situation/reports"
    return _http("POST", url, report)

def get_report(report_id: str) -> dict:
    return _http("GET", f"{ADMIN_SERVICE_URL}/api/admin/situation/reports/{report_id}")

def list_reports(user_id: str, team_ids: list, page=1, size=20) -> dict:
    return _http("GET", f"{ADMIN_SERVICE_URL}/api/admin/situation/reports",
                 params={"userId": user_id, "teamIds": ",".join(team_ids), "page": page, "size": size})

def create_share(report_id: str) -> dict:
    return _http("POST", f"{ADMIN_SERVICE_URL}/api/admin/situation/reports/{report_id}/share")
```

> `_http` 封装超时/异常/降级，遵循项目规范（中文日志、`{success,message,data}`）。

## 5. 数据流（生成 → 落库 → 查看）

```
生成中:  situation-service 内存持有 charts/map/narrative
         └─ SSE 实时推前端
done:    situation-service 聚合 → POST /api/admin/situation/reports (snapshot_json)
         └─ 返回 reportId
列表:    前端 → /api/situation/reports → situation-service → admin-service MySQL
详情:    前端 → /api/situation/reports/:id → situation-service → admin-service
分享:    前端 → /api/situation/share/:token → situation-service → admin-service
```

## 6. 迁移与兼容

- 无历史数据迁移负担（新功能）。
