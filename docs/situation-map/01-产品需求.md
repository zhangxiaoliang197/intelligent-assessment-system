# 01 · 产品需求

## 1. 背景与定位

系统现有智能问答、指标分析、评估分析、本体构建等模块。**态势图与智能问答、指标分析、评估分析并列，同为系统一级功能**（在 Portal 首页 `tools-row` 与三者并列入口），定位为把分散在知识库、指标、评估结果中的信息按地理分布与实时状态汇聚成一张可理解的态势画面：

- **综合态势感知**：把分散在知识库、指标、评估结果中的信息，按地理分布与实时状态汇聚成一张可理解的态势画面。
- **独立解耦**：不绑定本体模型与向量库，可被任意上层功能调用。
- **提问驱动**：用户在态势图直接用自然语言提问，由 LLM Agent 编排数据并生成图表/地图/说明。

## 2. 用户故事

### US-1 直接提问生成态势图
> 作为分析人员，我在态势图页面输入「某区域近期装备损耗与战备状态」，系统流式生成损耗趋势图、区域分布地图、战备指标雷达图，并给出当前态势介绍与逐图说明，我可以导出 PDF 汇报。

### US-2 从其他功能跳转生成
> 作为评估人员，我在「评估分析」得到某方案结论后，点击「生成态势图」，系统携带评估 ID 跳转到态势图页面并自动带入上下文，一键生成方案态势可视化。

### US-3 历史复用与分享
> 作为汇报人，我把上次生成的态势图从历史列表打开，导出图片插入汇报材料，或生成分享链接发给同事查看。

### US-4 地图同事嵌入
> 作为地图功能开发者，我按插槽契约把现有地图生成逻辑封装成 Vue 组件挂入态势图，消费同源数据集，并与图表联动（点地图区域 → 图表高亮）。

## 3. 功能范围

### 3.1 必做（v1）
- F1 态势图对话式工作区（路由 `/situation`，仿指标分析：左栏导航+历史、右侧对话区+执行步骤面板）+ 纯展示页（路由 `/situation/view/:reportId`，仅图表+地图+态势分析）。
- F2 后端 situation-service：草稿态、生成（Agent 编排）、流式推送（SSE）、持久化、列表/详情/分享。
- F3 LLM Agent tool-calling 编排，工具集覆盖现有服务（knowledge/indicator/evaluation/admin）+ 预留外部数据源。
- F4 统计图表（ECharts，注册表驱动，可扩展）：bar/line/pie/radar/gauge/scatter/heatmap/relation 等起步集。
- F5 地图插槽契约（容器+props+事件+共享状态），同事组件挂入；框架负责同源数据注入。
- F6 跨功能跳转：知识问答 / 指标分析 / 评估分析 → 态势图（草稿态+ID）。
- F7 持久化（走 admin-service MySQL）+ 历史列表 + 详情查看 + 分享链接。
- F8 导出 PDF/图片（前端 html2canvas + jsPDF）。
- F9 态势 Skill：支持目录、分类搜索、智能推荐、收藏、流程预览与一键应用；内置 30 个面向态势分析的专业 Skill，所选 Skill 必须进入生成编排上下文并影响数据源、图表和地图图层计划。

### 3.2 可做（v1.x）
- 态势产物编辑（手动调整图表/说明后另存）。
- 态势模板库（常用提问固化成模板，一键生成）。
- 多用户权限（按 `X-User-Id` / `X-Team-Ids` 隔离历史）。

### 3.3 非目标
- 不自建本体/向量库。
- 不实现地图生成逻辑本身（由同事完成）。
- 不做实时视频/流媒体融合。

## 4. 生成时序要求（关键）

> 来自用户明确反馈：**结论文本不应先于图表出现**。

时序必须为：

1. 数据获取（可流式推送 dataset）
2. **图表逐个产出**（chart_spec 流式推送，图表一个个冒出）
3. **地图图层产出**（map_layer 流式推送）
4. **态势介绍 + 图表说明**（narrative 流式推送，介绍当前态势 + 逐图解释，**不是结论先行**）
5. 生成完成 → 持久化 → 返回 reportId
6. 生成完成后，外部数据 tick 持续刷新图表/地图（chart_update / map_update）

详见 [03-Agent编排与生成时序.md](./03-Agent编排与生成时序.md)。

## 5. 产物定义

一份态势产物（Report）包含：

| 组成 | 内容 | 来源 |
|------|------|------|
| 元数据 | title / query / 来源功能 / user_id / team_ids / created_at | situation-service |
| 图表列表 | [{chartId, type, title, option(ECharts JSON), explanation}] | Agent 生成 |
| 地图数据 | points / routes / areas / layers（统一数据集子集） | Agent 生成 |
| 态势介绍 | 一段对当前态势的整体介绍（Markdown） | Agent 生成 |
| 图表说明 | 逐图解释，绑定 chartId（Markdown） | Agent 生成 |

产物可：持久化保存 / 列表查看历史 / 导出 PDF/图片 / 生成分享链接。

## 6. 交互流（主路径）

```
用户进入 /situation（对话式工作区）
  ├─ 直接提问：输入问题 → 智能推荐 Skill（可选）→ POST /generate → SSE 流式接收 → 渲染
  ├─ Skill 驱动：搜索/分类/收藏 → 预览流程与输出 → 选择推荐问题 → 生成
  └─ 跳转进入：URL 带 draftId → GET /draft/:draftId → 填充提问 → (可选自动) POST /generate

生成中：
  SSE 推送 plan → dataset → chart(逐个) → map_layer → narrative → done
  执行步骤面板同步展示各阶段步骤

生成后（AI 消息末尾操作）：
  ├─ 打开态势图：跳 /situation/view/:reportId 纯展示大图页（仅图表+地图+态势分析）
  ├─ 导出：前端截图 → PDF/图片下载
  ├─ 分享：生成 token → /situation/share/:token 公开查看
  └─ 历史：左栏历史记录点击加载 / /situation/list 全页管理
```

## 7. 非功能需求

- **性能**：单次生成首图应在数据就绪后 10s 内开始流式返回（依赖 LLM 与下游服务）。
- **可用性**：situation-service 单点失败不影响其他模块（独立服务）。
- **安全**：复用现有 `X-User-Id` / `X-Team-Ids` 头；分享链接 v1 走 token 公开访问（待 Q-04 确认）。
- **可维护**：遵循项目规范——中文注释、统一日志（logging_config.py）、`{success,message,data}` 响应、禁硬编码 URL/端口。
