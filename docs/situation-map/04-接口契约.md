# 04 · 接口契约

> 前端、后端、地图同事均以本章为对接依据。变更需同步通知所有对接方（见 README 协作约定）。
> 所有 REST 响应统一 `{success, message, data}`。所有 URL 经前端 `/api` 前缀代理（见 08 章）。

## 1. 路由前缀

- 前端调用：`/api/situation/*`（vite/nginx 代理到 situation-service:10257，rewrite 去掉 `/api`）
- SSE 流：`/api/situation/stream/:reportId`

## 2. REST 接口

### 2.0 态势 Skill

`GET /api/situation/skills?query=&category=&featured=&limit=100`

返回 30 个内置态势 Skill，以及当前用户可见的已发布/自有自定义 Skill；可按名称、描述、触发词、重点指标和分类检索。管理界面可传 `includeArchived=true` 查看自有归档项。响应 `data`：

```json
{
  "items": [{
    "id": "force-readiness",
    "name": "部队战备状态分析",
    "category": "战备保障",
    "description": "...",
    "triggers": ["战备状态"],
    "recommendedQuestions": ["评估各单位当前战备状态"],
    "inputHints": ["单位", "区域", "战备阈值"],
    "steps": ["汇总人员与可部署兵力", "关联装备完好和库存保障"],
    "dataSources": ["t_force", "t_equipment"],
    "chartTypes": ["radar", "gauge", "bar"],
    "mapLayerTypes": ["points", "areas"],
    "focusMetrics": ["综合战备率", "人员到位率", "装备完好率"],
    "parameters": [{"key":"区域","label":"区域","type":"text","required":false}],
    "source": "builtin",
    "isBuiltIn": true,
    "status": "published",
    "version": 1,
    "revision": 1
  }],
  "total": 30,
  "catalogTotal": 30,
  "categories": [{"name": "战备保障", "count": 7}]
}
```

- `GET /api/situation/skills/categories`：返回目录版本、总数和分类计数。
- `GET /api/situation/skills/:skillId`：返回单个 Skill 完整定义。
- `POST /api/situation/skills/recommend`：请求 `{ "query": "...", "limit": 3, "context": {} }`，综合文本命中、当前上下文、收藏与历史使用返回带 `score`、`matchedTriggers`、`recommendationReason` 的推荐结果。
- `POST /api/situation/skills/:skillId/apply`：请求 `{ "query": "...", "parameters": {} }`，返回经校验的参数、最终问题、执行步骤、数据源及可视化计划；用于生成前预检和第三方接入。
- `POST /api/situation/skills/:skillId/preflight`：同上请求；检查发布状态、参数类型/范围/选项、问题和数据源连通性，返回 `ready`、`complete`、`checks`、`errors` 与 `warnings`。生成接口会强制再次执行此检查。
- `GET /api/situation/skills/favorites`、`PUT /api/situation/skills/:skillId/favorite`：读取/更新当前用户收藏，请求 `{ "favorite": true }`。
- `GET /api/situation/skills/usage?limit=20`：返回当前用户执行记录及按 Skill 聚合的成功/使用次数。
- `POST /api/situation/skills`：创建自定义 Skill 草稿，请求 `{ "definition": {...} }`。
- `PUT /api/situation/skills/:skillId`：更新草稿；请求可带 `expectedRevision` 做乐观锁冲突检查。已发布项编辑后自动回到草稿态。
- `POST /api/situation/skills/:skillId/publish`：发布草稿，请求 `{ "changeNote": "..." }`。
- `DELETE /api/situation/skills/:skillId`：归档自定义 Skill；内置 Skill 只读且不可归档。
- `GET /api/situation/skills/:skillId/versions`、`POST /api/situation/skills/:skillId/rollback`：读取版本或按 `{ "version": 1 }` 回滚，回滚后进入草稿态。
- `GET /api/situation/skills/:skillId/markdown`：返回完整 `SKILL.md`、内容哈希、存储位置和当前用户是否可编辑。
- `PUT /api/situation/skills/:skillId/markdown`：请求 `{ "content": "...", "expectedHash": "sha256" }`；校验 YAML、ID、标题、分析步骤和危险字段后保存。哈希过期返回 `409`，无权限返回 `403`。

自定义 Skill、版本、用户收藏和使用记录持久化到 `SITUATION_SKILL_DB` 指定的 SQLite 文件；内置 Skill 的 Markdown 在线修改写入 `SITUATION_SKILL_MD_OVERRIDE_DIR`，保留镜像内置目录作为只读基线。Docker 使用 `/app/data` 持久化卷。生成接口只接受服务端目录中已发布的 Skill，并再次校验参数，不能通过客户端伪造定义。

### 2.1 创建草稿态（跨功能跳转入口）

`POST /api/situation/draft`

请求：
```json
{
  "source": "qa",
  "context": {
    "query": "某区域近期装备损耗与战备状态",
    "indicatorIds": ["ind_001"],
    "evaluationId": "eval_2026_001",
    "payload": {}
  },
  "userId": "local-admin",
  "teamIds": ["team_a"]
}
```

响应 data：
```json
{ "draftId": "d_20260810_xxxx", "expiresIn": 3600 }
```

说明：草稿态存内存/缓存（带 TTL，默认 1 小时）。`source` ∈ `qa | indicator | evaluation | manual`。`context` 各字段按来源可选。

### 2.2 读取草稿态

`GET /api/situation/draft/:draftId`

响应 data：
```json
{
  "draftId": "d_20260810_xxxx",
  "source": "qa",
  "context": { "query": "...", "evaluationId": "..." },
  "createdAt": "2026-08-10T10:00:00"
}
```

### 2.3 发起生成

`POST /api/situation/generate`

请求：
```json
{
  "query": "某区域近期装备损耗与战备状态",
  "draftId": "d_20260810_xxxx",
  "source": "qa",
  "context": {},
  "userId": "local-admin",
  "teamIds": ["team_a"],
  "autoRefresh": true,
  "skillId": "force-readiness",
  "skillParameters": {"区域": "A区域", "单位": "一营"}
}
```

响应 data：
```json
{ "reportId": "r_20260810_xxxx", "status": "generating", "streamUrl": "/api/situation/stream/r_20260810_xxxx" }
```

说明：立即返回 reportId，前端转 SSE 接收流式事件。`skillId` 可选；传入时服务端会校验并把 Skill 执行计划注入生成上下文，响应同时返回所用 Skill 摘要。`autoRefresh=true` 在生成完成后启动外部 tick（若有外部数据源）。

### 2.4 主动刷新（手动触发一次 tick）

`POST /api/situation/refresh/:reportId`

响应 data：`{ "updated": ["chartId_x", "layerId_y"], "status": "ready" }`

### 2.5 持久化产物列表

`GET /api/situation/reports?userId=&teamIds=&page=1&size=20`

响应 data：
```json
{
  "total": 42,
  "items": [
    { "reportId": "r_...", "title": "...", "query": "...", "source": "qa",
      "status": "ready", "createdAt": "...", "updatedAt": "..." }
  ]
}
```

> 实际数据落 admin-service MySQL（见 07 章）。situation-service 透传调用。

### 2.6 产物详情

`GET /api/situation/reports/:reportId`

响应 data：完整 Report 结构（见 §4）。

### 2.7 删除产物

`DELETE /api/situation/reports/:reportId` → `{success:true}`

### 2.8 生成分享链接

`POST /api/situation/reports/:reportId/share`

响应 data：`{ "shareUrl": "/situation/share/<token>", "token": "...", "expiresAt": null }`

### 2.9 公开查看（分享）

`GET /api/situation/share/:token` → 返回 Report 结构（不含敏感用户信息）。

### 2.10 更新产物（手动编辑后另存，v1.x）

`PUT /api/situation/reports/:reportId` （body 为部分 Report 字段）

## 3. SSE 流协议

`GET /api/situation/stream/:reportId`

- `Content-Type: text/event-stream`
- 每条事件：`event: <type>\ndata: <json>\n\n`
- nginx 需 `proxy_buffering off; proxy_read_timeout 3600s;`（见 08 章）

### 3.1 事件类型与 data 字段

#### event: plan
```json
{ "datasets": ["ds_knowledge","ds_indicator"], "chartsPlan": [{"type":"line","title":"损耗趋势"}], "mapPlan": [{"layerId":"loss_area"}] }
```

#### event: dataset
```json
{ "datasetId": "ds_indicator", "source": "indicator", "summary": "近30天装备损耗指标", "rows": 30 }
```

#### event: chart
```json
{ "chartId": "c_1", "type": "line", "title": "近30天损耗趋势",
  "option": { "xAxis": {...}, "series": [...] }, "datasetRef": "ds_indicator" }
```
`option` 为合法 ECharts option，数据内联。

#### event: map_layer
```json
{
  "layerId": "loss_area",
  "points": [{"name":"...","lng":104.0,"lat":30.0,"raw":"..."}],
  "routes": [{"name":"...","points":[{"lng":...,"lat":...}]}],
  "areas":  [{"name":"...","points":[{"lng":...,"lat":...}]}],
  "layerConfig": { "color":"#e74c3c", "opacity":0.8 }
}
```
> `points/routes/areas` 形状与现有 [GeoMap.vue](../../frontend/src/components/GeoMap.vue) props（`GeoPoint/GeoRoute/GeoArea`）一致，坐标为 WGS84（前端 gcoord 转 GCJ02）。

#### event: narrative
```json
{
  "intro": "当前某区域装备损耗呈上升趋势，战备状态总体平稳...",
  "explanations": [
    { "chartId": "c_1", "text": "该折线展示近30天损耗量，第18天出现峰值..." }
  ]
}
```
> intro 是**态势介绍**（描述性），explanations 是**逐图说明**，chartId 必须命中已产出的图表。

#### event: chart_update
```json
{ "chartId": "c_1", "option": { "xAxis": {...}, "series": [...] } }
```

#### event: map_update
```json
{ "layerId": "loss_area", "points": [...], "routes": [], "areas": [] }
```

#### event: done
```json
{ "reportId": "r_...", "status": "ready", "partial": false }
```
`status` ∈ `ready | partial | failed`；`partial=true` 表示部分图表失败。

#### event: error
```json
{ "stage": "dataset|chart|map_layer|narrative|llm", "message": "中文错误信息", "fatal": false }
```
`fatal=true` 时随后跟 `done(status=failed)`。

### 3.2 客户端重连
- 前端 EventSource 断开后自动重连，携 `Last-Event-ID`；situation-service 可选实现断点续推（v1 可不实现，重连后等下一次事件）。

## 5. 鉴权
- 所有非分享接口走现有 axios 拦截器，自动带 `Authorization` / `X-User-Id` / `X-User-Role` / `X-Team-Ids`（见 [services/api.ts](../../frontend/src/services/api.ts)）。
- 分享接口 `/share/:token` 不要求登录态。

## 6. 错误码约定
- 业务失败：HTTP 200 + `{success:false, message:"中文"}`
- 参数错误：HTTP 422 + FastAPI detail
- 未找到：HTTP 404 + `{success:false, message:"..."}`
- 前端拦截器已统一解包 `response.data` 并提取 `message`。
