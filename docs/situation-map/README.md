# 态势图功能设计文档

> 本目录为「态势图（Situation Map）」功能的项目文档，随仓库 git 同步，供多人远程协作修改、查看、对齐颗粒度。
> 所有文件使用中文撰写，遵循项目代码规范（`.trae/rules/project_rules.md`）。

## 一句话定位

态势图是一个**独立于本体模型与向量库**的**综合态势感知**功能：用户在态势图页面直接提问（或由知识问答 / 指标分析 / 评估分析跳转进入），由后端 **LLM Agent** 编排多源数据，**流式生成**一份包含**统计图表 + 地图 + 态势介绍与图表说明**的态势产物，支持**持久化、历史列表、导出 PDF/图片、分享链接**。

## 关键决策记录（ADR）

经多轮对齐确认，以下决策为当前基线。如需变更，请在对应章节提 Issue 或直接修改并在本表追加变更记录。

| 编号 | 决策点 | 结论 | 影响 |
|------|--------|------|------|
| ADR-01 | 业务定位 | **综合态势感知**（多源数据汇聚、地理分布 + 实时状态） | 图表/地图/模板方向偏态势大屏 |
| ADR-02 | 后端架构 | **新建独立 situation-service**（Python/FastAPI，端口 10257） | 彻底解耦本体/向量库，多一个进程 |
| ADR-03 | 生成机制 | **LLM 驱动（agent 式 tool-calling）** | LLM 决定调哪些数据接口、生成哪些图表/地图 |
| ADR-04 | 地图集成 | **前端组件插槽**（容器 + props + 事件 + 共享状态） | 同事把地图生成逻辑封装为 Vue 组件挂入 |
| ADR-05 | 数据来源 | **现有服务 API 为主 + 预留外部实时数据源接入点** | situation-service 编排现有服务，外部数据源可插拔 |
| ADR-06 | LLM 接入 | **situation-service 自带 LLM 客户端**（读 admin-service 配置，自跑 agent 循环） | 不依赖 qa-service 进程，独立可控 |
| ADR-07 | 实时刷新 | **SSE 实时推送**（agent 流式中间结果 + 生成完成后外部数据 tick） | 后端推送，前端被动接收 |
| ADR-08 | 生成时序 | **图表/地图先出，文本为「态势介绍 + 图表说明」随后**（非结论先行） | 改变 agent 输出顺序，见 03 章 |
| ADR-09 | 跨功能跳转 | **后端草稿态 + ID**（跳转前存态势请求拿 ID，带 ID 跳转） | 可复现、可分享，多一次请求 |
| ADR-10 | 产物形态 | **持久化保存 + 可导出 PDF/图片 + 分享链接** | 需存储 + 前端导出 |
| ADR-11 | 持久化存储 | **走 admin-service 的 MySQL**（situation-service 调 admin 新增 CRUD 接口，不直连 DB） | DB 表由 admin-service 管理 |
| ADR-12 | 导出渲染 | **前端 html2canvas + jsPDF 截图** | 无后端渲染依赖，复杂布局可能失真 |
| ADR-13 | 地图数据源 | **地图与图表同一数据源**（situation-service 产出的统一态势数据集，经 Pinia 注入两者；开发阶段可直连 DB 调试） | 插槽 props 契约以统一数据集为核心 |
| ADR-14 | 文档管理 | **新建独立文档**（本目录），随 git 同步 | 不追加到 PRD.md / 系统介绍.md |

## 名词表

| 名词 | 含义 |
|------|------|
| 态势图 / Situation Map | 本功能整体；也指生成的一份态势产物 |
| situation-service | 新建的态势图后端服务（Python/FastAPI，:10257） |
| 态势产物 / Report | 一次生成得到的完整结果（图表 + 地图 + 介绍/说明 + 元数据），可持久化 |
| 统一态势数据集 / Dataset | situation-service 产出的、同时喂给图表和地图的同源数据集合 |
| 态势介绍 / Narrative | 对当前态势的整体性介绍（非结论），位于文本区 |
| 图表说明 / Explanation | 逐图解释，与对应 chartId 绑定 |
| 草稿态 / Draft | 跨功能跳转前在后端创建的「态势请求」记录，带 ID |
| 地图插槽 / Map Slot | 前端为同事地图组件预留的容器 + 契约 |
| 工具 / Tool | LLM Agent 可调用的数据接口（query_knowledge 等） |

## 边界与非目标

- **不依赖**本体模型（ontology-service）与向量库（Qdrant / knowledge-service 的检索能力可作为工具被调用，但态势图自身不持有本体/向量库）。
- 态势图**不取代**知识问答 / 指标分析 / 评估分析，而是**消费**它们的能力并做可视化编排。
- 地图生成逻辑由**同事负责**，本功能只提供插槽契约与同源数据注入（见 06 章）。
- 界面框架**不固死**，布局可按场景灵活拼装（见 05 章「布局策略」）。
